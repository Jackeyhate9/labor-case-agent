# 架构决策记录

## ADR-001：模块化单体而非微服务

状态：接受

MVP 使用 Next.js Web + FastAPI API 的模块化单体。案件、证据、事实、时间线、计算、文书和导出按 service 边界拆分，但共享一个事务数据库。原因是本地部署、可审计和删除一致性比独立扩缩容更重要。若未来出现多人协作或重型 OCR 队列，再拆出 worker。

## ADR-002：离线优先与 provider 显式启用

状态：接受

SQLite 和本地文件存储为默认路径。LLM、embedding 默认 `disabled`；云 provider 必须显示将发送的材料范围并由用户显式启用。模型不可用时，上传、人工事实、时间线、Decimal 计算、模板文书与导出仍可使用。Mock provider 只用于自动化测试，并明确标识，不得出现在生产分析结果中。

## ADR-003：事实四层模型是不可绕过的领域约束

状态：接受

系统保存 Raw Evidence、Machine Extraction、Confirmed Fact、Legal Draft 四层。机器提取永远产生待核验事实；正式时间线、金额输入和文书只读取 `user_confirmed`。用户修正保留机器原值、修正值、确认时间和来源定位。拒绝与冲突事实不会被静默删除。

## ADR-004：金额由确定性 Decimal 函数计算

状态：接受

人民币金额在数据库和 API 中使用定点十进制语义。LLM 只解释公式和缺口，不计算最终金额。不确定输入保持为空，绝不按零处理；多笔付款、部分支付和第三人代付先归集到工资期间，再计算欠付额。

## ADR-005：证据文件不可公开寻址

状态：接受

原文件写入 `data/cases/{case_id}/original/`，处理结果写入 `processed/`，导出写入 `exports/`。下载和预览必须经 API 校验案件归属；文件名不参与真实磁盘路径拼接；拒绝可执行文件、路径穿越和超限文件。

## ADR-006：OCR 路由与可见降级

状态：接受

图片优先 RapidOCR 中文 provider，PDF/DOCX/TXT/CSV 使用确定性解析器。OCR 结果记录 engine、页码、区域、置信度和原文。provider 初始化或识别失败时状态为 failed/warning，并允许人工录入，不能返回硬编码文本。测试截图必须经过真实 OCR 调用。

## ADR-007：文书快照与不可变版本

状态：接受

每次生成文书冻结已确认事实 ID、证据 ID、金额版本和生成时间。事实变化后重新生成新版本，旧版本不可覆盖。导出前运行 Safety Review，阻断无来源金额、未确认事实和保证胜诉措辞。

## ADR-008：法律资料与案件证据分区

状态：接受

本地法律资料保存在 `knowledge/`，含来源、状态、版本、校验日期与哈希；案件证据只在案件存储与数据库。两者不共享检索空间。无法实时核验的法条显示“未实时核验”，第一阶段不让模型凭记忆生成条号。

## ADR-009：参考仓库只借鉴流程，代码复用需逐项许可

状态：接受

默认不复制任何参考仓库代码。只有许可证明确兼容、来源和文件清单可追踪时才允许复用；AGPL、Anti-996、无许可证或许可不明确的项目仅作理念和交互流程参考。
